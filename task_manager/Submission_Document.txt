TASK MANAGER CODEBASE EXERCISE

UNDERSTANDING PROJECT STRUCTURE

Initial Understanding:
- I thought this might be a website or web application.
- I thought it might use a database like SQL.
- I was not sure how the files connected to each other.

Final Understanding:
- This is a Python command line application (CLI).
- It uses a simple JSON text file (tasks.json) for storage, not a database.
- It has a layered "sandwich" architecture:
    * cli.py      = The buttons/remote control (user interface)
    * app.py      = The boss/manager (business logic)
    * storage.py  = The memory box (data saving/loading)
    * models.py   = The toy box (Task, Priority, Status definitions)

Misconceptions I Had:
- I Thought it was a web app. It is actually a terminal program.
- I Thought it used a database. It actually uses a JSON file.
- I did not understand the "layered" pattern at first.

Key Components and Responsibilities:
- TaskManager (app.py): Creates, updates, deletes, lists and exports tasks.
- TaskStorage (storage.py): Reads and writes tasks to tasks.json.
- Task (models.py): Defines what a task looks like and the rules it follows.
- CLI (cli.py): Turns user typed commands into calls to TaskManager.

Important Entry Points:
- User starts the program by running cli.py.
- cli.py creates a TaskManager.
- TaskManager uses TaskStorage to load saved tasks.

PART 3: UNDERSTANDING THE DOMAIN MODEL
---------------------------------------

Core Entities Identified:
1. Task: The main to-do item.
2. TaskPriority: Importance level (LOW=1, MEDIUM=2, HIGH=3, URGENT=4).
3. TaskStatus: Current stage (TODO, IN_PROGRESS, REVIEW, DONE).

Entity Relationships:
- A Task HAS one Priority.
- A Task HAS one Status.
- A Task HAS many Tags (list of words).

Business Rules Found in models.py:
1. update() Rule: When a task is changed, record the current time as updated_at.
2. mark_as_done() Rule: When finished, set status to DONE and record completed_at.
3. is_overdue() Rule: A task is overdue if its due_date passed AND it is not DONE.

Glossary of Domain Terms:
- Task: A to-do item or chore.
- Priority: Importance level from 1 (low) to 4 (urgent).
- Status: Current workflow stage (todo, in_progress, review, done).
- Due Date: Deadline for completing the task.
- Tags: Labels used to group similar tasks together.
- Overdue: The deadline has passed but the task is not finished.
- Completed At: The exact timestamp when the task was marked done.
- Domain Model: All the important things and rules that make up the application.

Quiz Answers:
1. The 3 main entities are Task, TaskPriority, and TaskStatus.
2. No, a DONE task cannot be overdue.
3. completed_at gets set to the current date and time.
4. No, priority only allows 1, 2, 3, or 4.
5. The overdue rule lives in models.py.

STRATEGIES FOR APPROACHING UNFAMILIAR CODE IN THE FUTURE
---------------------------------------------------------
1. Run it first: See what the program does before reading how it works.
2. Draw the layers: Identify the architecture pattern (CLI, web, API, etc.).
3. Find the entry point: Where does the program start? (usually main() or app.py)
4. Look for similar features: Before adding something new, find something like it.
5. Ask the domain questions: What are the "things" and "rules" in this app?
6. Make small changes: Change one thing, test it, then change the next thing.
7. Keep a glossary: Write down weird words so you do not forget what they mean.
