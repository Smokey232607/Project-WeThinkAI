
DOMAIN MODEL FINDINGS

1. CORE ENTITIES (The Main Toys)

- Task: The main thing - a to-do item
- Task Priority: How important (1=LOW, 4=URGENT)
- Task Status: What stage (todo, InProgress, review, done)

2. ENTITY DIAGRAM (How They Connect)

Task has:
  → one Priority (Task Priority)
  → one Status (Task Status)  
  → many Tags (list of words)

3. BUSINESS RULES I FOUND

RULE 1: Update Task

Location: models.py, Task. Update()
What it does: When someone changes a task, write down the new time.
Why it matters: So we know when the task was last touched.

RULE 2: Mark as Done

Location: models.py, Task. mark as done()
What it does: Change status to DONE and remember the finish time.
Why it matters: So we can track completion times for statistics.

RULE 3: Check Overdue

Location: models.py, Task.is overdue()
What it does: A task is late if deadline passed AND it's not done yet.
Why it matters: So the app can warn about late tasks.

Note: DONE tasks can NEVER be overdue!

4. GLOSSARY (Word List)
- Task: A to-do item
- Priority: Importance level 1 to 4
- Status: Current stage in workflow
- Due Date: Deadline
- Tags: Labels for grouping
- Overdue: Late (past deadline, not done)
- Domain Model: The toy box of things and rules in the app

5. HOW THE TOYS CONNECT (Relationships)

A Task "has" one Priority.
A Task "has" one Status.
A Task "has many" Tags.

Like a person:
  → wears one hat (Priority)
  → has one mood (Status)
  → carries many stickers (Tags)


6: My Mini Dictionary


Task          → A to-do item or chore the app keeps track of.
TaskPriority  → How important a task is (1=LOW, 2=MEDIUM, 3=HIGH, 4=URGENT).
TaskStatus    → What stage a task is in (TODO, IN_PROGRESS, REVIEW, DONE).
due_date      → The deadline — the day the task should be finished.
tags          → Little labels you stick on tasks to group them together.
overdue       → When a task's deadline passed but it is NOT done yet.
completed_at  → The exact date and time a task was marked as DONE.
created_at    → The exact date and time a task was first made.
updated_at    → The last time anything on the task was changed.
Domain Model  → All the important "things" and "rules" that make up the app.

 7: TEST MY KNOWLEDGE (My Answers)

QUESTION 1: What are the 3 main toys (entities) in the toy box?
MY ANSWER: Task, TaskPriority and TaskStatus.

QUESTION 2: If a Task's due date was yesterday but its status is DONE is it overdue?
MY ANSWER: No! Because the rule says a task is only overdue if it is NOT done yet.

QUESTION 3: What happens to completed at when you mark a task as done?
MY ANSWER: It gets set to the exact current date and time right now.

QUESTION 4: Can a Task have a priority of 5?
MY ANSWER: No! The Priority only allows 1, 2, 3 or 4. It's like a die with only 4 sides.

QUESTION 5: Where does the overdue rule live in app.py, cli.py or models.py?
MY ANSWER: models.py! The Task itself knows if it's late. That's where the rule belongs.
